How MinePay Enforces ACID Properties:

A
Atomicity (All-or-Nothing):

Transfer is wrapped in BEGIN and COMMIT. If any debit, credit, or PIN verification fails, ROLLBACK immediately executes.

C
Consistency (Invariants):

Schema enforces CHECK (balance >= 0.00). Total currency in the system remains conserved before and after every transfer.

I
Isolation (No Race Conditions):

Row-level locks SELECT ... FOR UPDATE lock accounts in sorted order (ORDER BY account_id ASC), completely eliminating double-spending and deadlocks.

D
Durability (Persistent Ledger):

Committed records are permanently written to write-ahead logs (WAL) in PostgreSQL with foreign keys locked by ON DELETE RESTRICT.

-- PostgreSQL 3NF Normalized Schema
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    phone_number VARCHAR(15) UNIQUE NOT NULL,
    upi_handle VARCHAR(50) UNIQUE NOT NULL
);

CREATE TABLE accounts (
    account_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(user_id) ON DELETE RESTRICT,
    account_number VARCHAR(20) UNIQUE NOT NULL,
    balance NUMERIC(12, 2) NOT NULL CHECK (balance >= 0.00),
    security_pin_hash VARCHAR(64) NOT NULL
);

CREATE TABLE transactions (
    transaction_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    sender_account_id UUID REFERENCES accounts(account_id) ON DELETE RESTRICT,
    receiver_account_id UUID REFERENCES accounts(account_id) ON DELETE RESTRICT,
    amount NUMERIC(12, 2) NOT NULL CHECK (amount > 0.00),
    status VARCHAR(20) CHECK (status IN ('PENDING', 'SUCCESS', 'FAILED'))
);
